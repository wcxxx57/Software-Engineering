# 自增长课程大纲知识库、个性化计划与知识树

> 用途：PPT 技术展示稿。内容以提交 `2c9f7a8` 的实际代码为准；“已接入”指代码与接口已经接入项目，并不等同于生产环境已经部署并验收。

---

## 第 1 页｜我们解决什么问题

### 从“临时让 AI 编计划”升级为“知识库约束下的个性化计划”

- **原有风险**：模型可能在生成当下自行决定课程范围，计划依据不稳定，也无法把学习完成情况映射到统一知识结构。
- **本次改造**：先从自有课程大纲知识库中选择并固定一个课程版本；课前测和学习计划都只能引用该版本中的知识节点。
- **最终体验**：同一份学习计划既可在线性时间线中完成任务，也可切换到知识树，直观看到任务点亮了哪些知识点。

### 一句话架构

`学生主题 → 选择/补充权威大纲 → 固定大纲版本 → 课前测 → 个性化计划 → 任务—知识点映射 → 知识树反馈`

## 第 2 页｜输入是什么

### 1. 创建学习主题时的用户输入

前端保持原有创建主题接口 `POST /api/v1/study-subjects`，核心字段为：

- `subject`：想学习的主题，例如“Python basics”“Python 基础”；
- `language`：`PYTHON / JAVA / CPP / GO / RUST`；
- `target`：学习目标，例如“完成爬虫小项目”；
- `total_stages`：希望拆分成多少个学习阶段。

### 2. 生成课前测和计划时的系统输入

- 已固定的课程模板、版本、来源和完整知识节点树；
- 学生课前测的答案与自信度；
- 学习者画像：年龄、简介、经验值、打卡情况等；
- 历史学习情况：已完成主题、已完成知识节点、近期错题关联的薄弱知识节点；
- 计划形状约束：阶段数量，以及每阶段任务数量。

**关键点**：模型拿到的是数据库重新读取的“大纲快照”，不是未入库的网页临时文本。

## 第 3 页｜知识库如何参与：先看现有模板，再考虑补库

### 初始课程目录

服务启动和迁移后会幂等写入 16 个已发布模板：

- Python、Java、C++、Go、Rust：每种语言各有“语言基础”和“进阶/项目实践”两类模板；
- 数据结构与算法、计算机网络、操作系统、数据库原理、计算机组成原理、软件工程。

每个模板包含：规范课程名、语言、别名、版本、来源信息和两层以上的知识节点树。例如 Python 基础模板覆盖“环境与程序结构 → 变量类型 → 流程控制 → 函数模块 → 容器与文件”。

### 不是硬编码名称匹配

创建主题后，后端把**数据库当前全部已发布模板摘要**（模板名、别名、知识点、版本）交给课程采集任务。模型基于主题、语言和目标进行语义选择，并只能返回已有模板 ID 或“无匹配”。

- “Python basics”“Python基础”等别名是模板的语义线索；
- 不会因为只匹配到一个固定字符串就直接决定课程；
- 即使模型选择了模板，后端仍会校验该 ID 当前存在且状态为 `PUBLISHED`。

## 第 4 页｜生成流程：本地优先，未命中才联网补库

```text
创建主题
  ↓
写入 study_subject，状态 CURRICULUM_QUEUING，并发送 RabbitMQ 任务
  ↓
AI 在“当前已发布模板”中语义选择
  ├─ 选中已有模板：回调确认模板 → 从数据库加载固定大纲 → 发起课前测
  └─ 无匹配：Tavily 在教育白名单内搜索（最多 3 条）
       ↓
     LLM 将候选课程大纲结构化为知识树
       ↓
     后端校验并入库；成功后重新从数据库加载 → 发起课前测
```

### 联网补库的边界与校验

- 默认白名单：`icourse163.org`、`shuishan.net.cn`，可由环境变量扩展高校官方域名；
- 搜索接口使用 Tavily 的 `include_domains`；仅接收 HTTPS、白名单域名、无跟随重定向的候选；单条内容最多保留 30,000 字符；
- 自动发布要求包括：来源合规、匹配分数不低于默认 `0.85`、知识树结构完整、节点有效、内容哈希未重复；
- 校验不通过但来源合规：保存为 `PENDING_REVIEW`，主题失败并退款；来源不合规或采集失败：直接失败并退款；
- 待审核模板可用离线命令 `curriculum_review list / publish / reject` 处理。

**因此，运行时不会直接拿未落库网页给计划模型生成计划。**

## 第 5 页｜Skill 如何参与个性化生成

### 生产 Skill：`generate-course-plan`

Skill 位于 `services/core-generation/skills/generate-course-plan/`，由三部分组成：

- `SKILL.md`：规定“课程树是唯一知识权威”“任务只能引用输入树中的节点”“保持先修顺序、优先补弱项”；
- `runner.py`：汇总节点键集合，并校验模型生成任务的节点引用；
- Pydantic 数据模型：约束阶段、任务、题目和知识节点字段的结构。

### 生成计划时发生的事

1. 用户提交课前测后，后端重新查询该主题固定的 `curriculum_template_id`；
2. 组合课前测结果、画像、历史已完成节点、薄弱节点，以及固定大纲快照，发送给计划生成服务；
3. Skill 约束模型按既定阶段数和任务数生成任务，每项任务必须给出至少一个 `knowledge_node_key`；
4. 回调时二次校验：阶段数、每阶段任务数、节点引用和非空映射必须正确；否则任务失败，沿用退款流程。

这使 AI 负责“因人而异地编排”，而不是重新发明课程知识边界。

## 第 6 页｜结果保存在哪里

### PostgreSQL：长期、可追溯的数据

| 数据 | 表/字段 | 用途 |
| --- | --- | --- |
| 课程模板 | `curriculum_template` | 规范课程名、别名、版本、发布/待审核状态 |
| 权威来源 | `curriculum_source` | 平台、学校、教师、URL、内容哈希、审核状态 |
| 知识树 | `curriculum_node` | 节点键、父节点、层级、顺序、描述 |
| 主题绑定 | `study_subject.curriculum_template_id` | 锁定本次学习计划所用模板版本 |
| 课前测映射 | `pretest_problem.curriculum_node_id` | 每道题对应的知识节点 |
| 计划映射 | `study_task_curriculum_node` | 每个学习任务覆盖的一个或多个知识节点 |
| 线性计划 | 既有 `study_stage`、`study_task` | 阶段、任务、解锁与完成状态 |

### RabbitMQ：异步任务传递，不承担长期事实存储

- 课程选择/补库：`zhiying.curriculum`；
- 课前测和计划生成：沿用生成服务消息队列；
- 回调成功后才将课程、题目、阶段、任务和映射事务性写入 PostgreSQL。

### 版本原则

课程结构变化时创建新版本，不覆盖旧版本；已经创建的学习主题始终保留原来的模板 ID，因此历史计划可复现。

所以可以准确表述为：**功能已接入网站代码与服务编排；生产环境是否已生效，取决于上述迁移、环境变量和部署是否完成。**

## 第 8 页｜展示时可用的讲解稿（约 45 秒）

“学生输入想学的主题、语言、目标和学习阶段数后，系统不会立刻让 AI 自由生成计划。它先把我们自己的课程模板库交给模型，从当前已发布的大纲中语义选择最合适的一门课，并把模板版本固定到学生主题上。若没有可用模板，才会在 MOOC、水杉等教育白名单内检索，经过结构、来源、匹配度和去重校验后入库，再从数据库读出来继续生成。随后，课前测和学习计划都必须绑定知识节点。这样完成一个任务后，我们既能在线性计划里推进，也能在知识树里看到对应节点和父节点被点亮。整个过程把 AI 的个性化能力保留下来，同时让课程边界、来源和学习进度都可追溯。”

---

## 可在答辩中主动说明的边界

- 初始 16 个模板是系统内置的标准化目录与知识树骨架；对每门课的具体权威网页来源仍可通过补库和审核机制持续丰富。
- 联网补库的默认实现是 Tavily 搜索 API 返回的白名单候选内容，不是对任意网站的自由爬取。
- 当前知识树的“拖动”指拖动画布浏览；为了防止用户改变课程结构，知识节点本身是只读且不可拖动的。
